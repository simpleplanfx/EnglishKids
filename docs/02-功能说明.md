# 02 · 功能说明

> 这一篇讲每个功能「具体怎么运作」，包括评分算法和数据规则。
> 面向后续维护和二次开发。

---

## 一、界面结构

应用共 9 个页面（`js/app.js` 中的 `SCREENS` 常量）：

```
SCREENS = ['home', 'units', 'learn', 'listen', 'speak', 'write', 'result', 'wrong', 'me']
```

底部有 3 个常驻 Tab（`TAB_SCREENS`），可随时切换：

| Tab | 页面 | 作用 |
| --- | --- | --- |
| 首页 | `home` | 词书列表，展示每本书的掌握进度环 |
| 错词本 | `wrong` | 集中复习答错的词 |
| 我的 | `me` | 星星总数、连续打卡、每日统计、自定义词书 |

其余为流程页面，按学习动线推进：

```
home ──选词书──> units ──选单元──> learn ──┬──> listen   (听)
                                           ├──> speak    (跟读)
                                           └──> write    (默写)
                                                  │
                                                  v
                                               result  (结果页)
```

页面切换由 `show(name)` 统一控制，同时负责 Tab 高亮同步。

## 二、模块一：听（磨耳朵）

**入口**：`listen` 页面
**目标**：建立单词「音 — 形 — 义」的关联

### 功能

- 单词与例句朗读
- **英音 / 美音**切换（`pickVoice` 按 `en-GB` / `en-US` 匹配系统语音）
- 语速调节，默认 **0.85x**（略慢于正常语速，适合孩子跟听）
- 支持循环播放

### 实现

发音走 `js/speech.js` 的 `speak(text, opt)`，按**三级降级**策略：

```
1. 原生 TTS（Android）  → AndroidTTS 桥，离线，首选
2. 网页 TTS（浏览器）   → window.speechSynthesis
3. 在线发音（有道）      → 需联网，兜底
```

优先级由 `opt.source` 控制，页面默认 `system`（原生优先）。
在安卓 WebView 中走原生 `TextToSpeech`，**完全离线可用**。

### 回调机制

原生播报结束时，通过 `UtteranceProgressListener` 回调网页：

- `onDone` → `window.__onTtsEnd()`
- `onError` → `window.__onTtsError()`

页面据此更新按钮状态（如「播放中」→「播放」）。

## 三、模块二：跟读（开口练）

**入口**：`speak` 页面
**目标**：让孩子开口，并给出可理解的反馈

### 流程

1. 页面显示目标单词
2. 点击录音 → 请求麦克风权限 → 开始采集
3. 识别结果回传 → 与标准发音比对 → 给出 0–100 分
4. 显示「你说的是：xxx」，支持回放自己的录音

### 识别通道

| 环境 | 通道 | 超时 |
| --- | --- | --- |
| 安卓 WebView | 原生 `AndroidASR` 桥（系统 `SpeechRecognizer`） | 7 秒 |
| 浏览器 | Web Speech API (`SpeechRecognition`) | 6 秒 |

`canScore()` 会在开始前检测环境是否支持，不支持则隐藏评分入口，
避免出现点了没反应的情况。

### 评分算法

核心是 `similarity(target, heard)`，基于 **Levenshtein 编辑距离**：

```
1. 归一化 norm()
   转小写 → 剥离非字母数字字符 → 合并空白

2. 完全一致 → 100 分

3. 逐词最佳匹配
   把目标与识别结果都按空格拆词
   目标每个词，在识别结果中找相似度最高的那个
   取所有目标词得分的平均
   （这样短语 "police officer" 部分读对也能拿分）

4. 单词相似度 levRatio()
   基础分 = (1 - 编辑距离 / 较长串长度) × 100
   若一方包含另一方（如读出 "teach" vs 目标 "teacher"）
   → 保底 88 分
```

**设计考量**：孩子发音不可能标准，评分过严会打击积极性。
所以算法刻意宽松——包含关系给保底分，短语按词分别计分，
只要孩子「大致读出来了」就能拿到正反馈。

> 若 7 秒内无识别结果（环境嘈杂或识别服务不可用），
> 返回 `null`，页面降级为**自评模式**（孩子自己判断读得对不对）。

## 四、模块三：默写（检验掌握）

**入口**：`write` 页面
**目标**：从「认得」到「写得出」

### 两种模式

| 模式 | 提示 | 考察 |
| --- | --- | --- |
| **看中文写英文** | 显示中文释义 | 拼写 |
| **听发音写英文** | 播放读音 | 听力 + 拼写 |

### 判分规则

输入与标准答案比对（忽略大小写与首尾空格）。
答错自动进错词本。

## 五、进度与数据体系

所有数据由 `js/store.js` 管理，存 `localStorage`（键名 `ekids_v1`），
**只存本地，不上传**。

### 单词掌握状态

每个词的统计对象：

```js
{ n: 练习总次数, r: 答对次数, w: 当前连续答对次数, bad: 是否在错词本 }
```

`mark(bookId, en, ok)` 的更新规则：

| 情况 | 变化 |
| --- | --- |
| 答对 | `n++`, `r++`, `w++`；当 `w >= 3` 时 `bad = 0`（**移出错词本**） |
| 答错 | `w = 0`（连续中断），`bad = 1`（**进入错词本**） |

**掌握判定**：`isMastered()` = 连续答对 **3 次**（`w >= 3`）。

> 这里的「连续」是关键：答错一次就清零，避免孩子靠次数刷掌握度。

### 激励体系

| 项目 | 说明 |
| --- | --- |
| 星星 | 答对奖励，累计展示在「我的」页 |
| 连续打卡 | `streak()` 逐日回溯，今天还没学则从昨天算起（不会一早就断签） |
| 每日统计 | 记录当天练习词数、正确数、学习时长 |
| 进度环 | `ring(pct)` 以 SVG 圆环展示每本书的掌握百分比 |

### 错词本

`wrongList()` 遍历所有 `bad = 1` 的词。
在错词本中连续答对 3 次后自动移出（`bad = 0`）。

### 自定义词书

`addCustom(bookId, unitName, words)` 支持在 App 内自建词书与单元，
存于 `data.custom`，与内置词书合并展示。

## 六、离线能力

- 网页、CSS、JS、词库、图标全部打包进 `assets/`，随 APK 安装
- `sw.js`（Service Worker）缓存静态资源，二次启动秒开
- 加载词库 `loadJSON()` 有**双重兜底**：XHR 失败则回退 `fetch`
- 三大功能中，**听**与**默写**完全离线；**跟读**依赖系统识别服务，部分机型需联网

## 七、权限说明

| 权限 | 用途 | 拒绝后影响 |
| --- | --- | --- |
| `RECORD_AUDIO` | 跟读录音与评分 | 跟读不可用，听/默写正常 |
| `INTERNET` | 在线发音兜底、系统识别服务 | 离线功能不受影响 |
| `ACCESS_NETWORK_STATE` | 判断网络可用性 | 仅影响在线兜底策略 |

权限在首次进入时申请，不强制；拒绝也不会导致应用崩溃或退出。
