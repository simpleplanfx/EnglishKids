## 二、本机构建环境的六个坑

在 Windows 本机从零搭建 Android 构建环境时，连续遇到 6 个问题。
它们都与代码无关，纯粹是 **Windows 环境特性 + 网络不稳 + PowerShell 行为** 导致的，
但每一个都足以让构建中断。

### 坑 1 — .bat 中文变乱码

**现象**

双击 bat 后命令行报错：

```
'他给派?' 不是内部或外部命令
```

**根因**

`cmd.exe` 读取 `.bat` 文件时，用的是**系统默认代码页**（中文 Windows 是 GBK / CP936），
而文件实际保存为 UTF-8。中文字符被按 GBK 解码成乱码，cmd 把它当成了命令名。

**解法**

`.bat` 文件**必须保持纯 ASCII**，一个非 ASCII 字节都不能有。
所有中文输出改由 PowerShell 脚本负责（`.ps1` 用 UTF-8 **带 BOM** 保存即可正常显示中文）。

现在 `scripts/run_build.bat` 顶部有醒目注释，提醒后来者不要往里加中文：

```bat
REM  IMPORTANT: This file MUST stay pure ASCII.
REM  cmd.exe reads .bat files using the system codepage (GBK/936
REM  on Chinese Windows). Any non-ASCII byte will be mis-decoded.
```

> **校验方法**：`LC_ALL=C grep -c '[^ -~\r\n\t]' run_build.bat` 应输出 `0`

---

### 坑 2 — 改了文件却不生效（Windows 文件锁）

**现象**

明明已经把 bat 改成纯 ASCII 了，重新运行**还是同样的乱码错误**。

**根因**

这是**文件锁**，不是编码问题。之前的 cmd 窗口还开着、仍占用着那个 `.bat` 文件，
Windows 因此拒绝写入。表面上「保存成功」，实际上磁盘上的文件根本没被替换——
运行的仍是旧版本。

**解法**

1. 先**关闭所有还在运行的 cmd 窗口**
2. 删除旧文件，换一个**新文件名**重新创建（避开残留的句柄）

本项目因此把 `一键打包APK.bat` 换成了 `scripts/run_build.bat`。

> **教训**：Windows 上「改了没效果」时，先怀疑文件锁，而不是怀疑改动本身。
> 验证方式：改完后用 `ls -la` 确认文件大小与修改时间确实变了。

### 坑 3 — JDK 下载中断

**现象**

```
Invoke-WebRequest : 基础连接已经关闭: 发送时发生错误。
```

**根因**

JDK 压缩包约 190MB，下载过程中连接被中途掐断。
最初用的是 Adoptium API（会 302 跳转到 GitHub），跳转 + 大文件，失败率很高。

**解法**

改为**多源 + 重试**策略（`scripts/build_apk.ps1` 步骤 1）：

```powershell
$jdkUrls = @(
    @{ n = 'Microsoft Build of OpenJDK (Azure CDN)'; u = 'https://aka.ms/...' },
    @{ n = 'Azul Zulu (Cloudflare CDN)';             u = 'https://cdn.azul.com/...' },
    @{ n = 'Adoptium API -> GitHub (回退源)';        u = 'https://api.adoptium.net/...' }
)
```

- 3 个源依次尝试，每个源内部重试 2 次，失败间隔 4 秒
- 模拟浏览器 `User-Agent`（部分 CDN 拒绝脚本式请求）
- 超时放宽到 600 秒

优先用**直连 CDN**（前两个源），把「API 跳转」作为兜底——跳转环节最容易断。

### 坑 4 — Android SDK 下载中断

**现象**

和坑 3 一模一样的 `基础连接已经关闭`，发生在下载 `commandlinetools-win-*.zip` 时。

**根因**

同类问题。Android cmdline-tools 只有 Google 官方源，没有替代镜像可选。

**解法**

既然换不了源，就换**下载工具**——双重策略（步骤 2）：

```powershell
# 方案 A：Invoke-WebRequest 重试 3 次
# 方案 B：全部失败后改用 curl.exe 再试 3 次
& curl.exe -L --retry 3 --retry-delay 5 --connect-timeout 30 --max-time 900 ...
```

`curl.exe`（Windows 10+ 自带）对断流的容错明显优于 `Invoke-WebRequest`，
自带重试、延迟、超时参数。

**关键细节**：下载完必须**校验文件大小**，防止拿到错误页面还当成成功：

```powershell
if ((Test-Path $ctZip) -and ((Get-Item $ctZip).Length -gt 1000000)) { $ok = $true }
```

### 坑 5 — Gradle 找不到工程

**现象**

```
FAILURE: Build failed with an exception.
* What went wrong:
Directory 'D:\software\EnglishKidsAPK' does not contain a Gradle build.
A Gradle build should contain a 'settings.gradle' or 'settings.gradle.kts' file...
```

**根因**

脚本里这样调用：

```powershell
$gradlew = Join-Path $ProjectDir 'gradlew.bat'
& $gradlew assembleDebug          # ← 错在这
```

`$gradlew` 的路径是对的（指向 `EnglishKidsApp\gradlew.bat`），但 **Gradle 是依据
「当前工作目录」寻找 `settings.gradle` 的，而不是依据 `gradlew.bat` 自身所在位置**。
PowerShell 的当前目录仍停在父目录 `D:\software\EnglishKidsAPK`，于是 Gradle 去那儿找，
自然找不到。

**解法**

调用前显式切换工作目录：

```powershell
Push-Location $ProjectDir
try {
    & $gradlew assembleDebug --no-daemon --stacktrace
    $gradleExit = $LASTEXITCODE
} finally {
    Pop-Location
}
```

用 `try/finally` 保证即便编译抛异常，工作目录也能恢复，不污染后续步骤。

### 坑 6 — 编译明明成功，脚本却报失败 ⭐ 最隐蔽

**现象**

```
BUILD SUCCESSFUL in 1m 21s
31 actionable tasks: 31 executed
Gradle 编译失败，请查看上方错误。        ← 误报！
```

Gradle 自己说成功了，脚本却判定失败，导致最后的 APK 复制步骤没执行。

**根因**

这是 **PowerShell 的 `$LASTEXITCODE` 行为陷阱**。

```powershell
try {
    & $gradlew assembleDebug        # gradlew 返回 0（成功）
} finally {
    Pop-Location                    # ← 这个 cmdlet 会覆盖 $LASTEXITCODE
}
if ($LASTEXITCODE -ne 0) { throw }  # 读到的已不是 gradlew 的退出码
```

`$LASTEXITCODE` 反映的是「最后一个原生命令」的退出码。
`finally` 块里的 `Pop-Location` 执行后，它记录的值已不再属于 `gradlew`。

**解法**

紧跟在原生命令之后，**立即**把退出码存进变量：

```powershell
& $gradlew assembleDebug --no-daemon --stacktrace
$gradleExit = $LASTEXITCODE        # 必须在 Pop-Location 之前！
```

判断时用变量 `$gradleExit`，而不是再读自动变量 `$LASTEXITCODE`。

> **通用教训**：在 PowerShell 里，凡是「原生命令 + try/finally」的组合，
> 都要在 finally 执行前捕获退出码。

## 三、经验总结

| 类别 | 结论 |
| --- | --- |
| Windows 批处理 | `.bat` 必须纯 ASCII；中文输出交给 UTF-8 BOM 的 `.ps1` |
| Windows 文件 | 改了没生效先查文件锁，关闭占用进程或换文件名 |
| 大文件下载 | 多源 + 多次重试 + 浏览器 UA + 放宽超时 + **校验文件大小** |
| 下载工具 | `curl.exe` 断流容错优于 `Invoke-WebRequest`，值得作为备用 |
| 调用 Gradle | 必须 `Push-Location` 到工程根，Gradle 认 cwd 不认脚本位置 |
| PowerShell 退出码 | 原生命令后**立即**存变量，`try/finally` 会覆盖 `$LASTEXITCODE` |
| 脚本幂等性 | 每步都先检测「是否已存在」，中断后重跑能秒过已完成步骤 |
