## 一、修改词库（最常见的维护操作）

词库文件：`app/src/main/assets/data/words.json`

### 数据结构

```json
{
  "meta": {
    "name": "小学英语听说默写词库",
    "region": "上海·沪教版/牛津上海版",
    "generated": "2026-09-04",
    "bookCount": 13,
    "wordCount": 1337
  },
  "books": [
    {
      "id": "hj3a",
      "grade": 3,
      "term": 1,
      "title": "三年级上册",
      "subtitle": "沪教版（五四制·2024 新教材）",
      "tag": "当前教材",
      "count": 151,
      "units": [
        {
          "name": "人物、家庭成员与职业",
          "words": [
            { "en": "teacher", "zh": "教师；老师", "ph": "ˈtiːtʃə(r)", "ph_us": "ˈtiːtʃər" }
          ]
        }
      ]
    }
  ]
}
```

### 字段说明

| 层级 | 字段 | 必填 | 说明 |
| --- | --- | --- | --- |
| book | `id` | ✅ | 唯一标识，**不要改动已有值**，否则会丢失该书的进度记录 |
| book | `title` | ✅ | 显示名称，如「三年级上册」 |
| book | `tag` | | 角标文字，如「当前教材」「扩展」「小升初衔接」 |
| book | `count` | | 词数（用于列表展示，建议与实际一致） |
| unit | `name` | ✅ | 单元名，如「学校与学习用品」 |
| word | `en` | ✅ | 英文 |
| word | `zh` | ✅ | 中文释义 |
| word | `ph` | | 英式音标（可为空字符串） |
| word | `ph_us` | | 美式音标（可为空字符串） |

### 操作步骤

1. 编辑 `words.json`（可用 VS Code，或任意文本编辑器）
2. 若改动了 `meta` 里的统计，同步更新 `bookCount` / `wordCount` / `generated`
3. 校验 JSON 格式合法：

```bash
python -c "import json;d=json.load(open('app/src/main/assets/data/words.json',encoding='utf-8'));print('OK 词书数:',len(d['books']))"
```

4. 重新编译：`./gradlew assembleDebug`
5. 提交：

```bash
git add app/src/main/assets/data/words.json
git commit -m "chore(words): 更新三年级上册 Unit 5 词汇"
```

### ⚠️ 注意事项

- **`id` 不要随便改**。进度记录以 `bookId|单词` 为键存于手机本地，
  改 `id` 会导致孩子已积累的进度「消失」。
- **音标允许为空**。App 会正常显示，只是不显示音标行。
- **改 JSON 后必须重新编译 APK**，因为词库是打包进 `assets/` 的，不是运行时下载。
- App 内的**自定义词书**存在手机 localStorage，不受此文件影响，
  但清除应用数据会丢失（内置词书不会）。

## 二、版本管理

版本号在 `app/build.gradle`：

```gradle
defaultConfig {
    versionCode 1          // 整数，每次发布必须 +1，系统据此判断升级
    versionName '1.0'      // 展示给用户的版本字符串
}
```

### 发布新版本流程

1. 改代码或词库
2. 递增版本号：

```gradle
versionCode 2
versionName '1.1'
```

3. 编译验证：`./gradlew assembleDebug`
4. 更新 `CHANGELOG.md`，在顶部新增版本条目
5. 提交并打标签：

```bash
git add .
git commit -m "feat: 新增 XX 功能"
git tag -a v1.1 -m "v1.1 —— 新增 XX 功能"
git push origin main --tags
```

6. 把新 APK 上传到 GitHub Release

### 版本号规则

遵循[语义化版本](https://semver.org/lang/zh-CN/)：

| 变更类型 | 版本 | 例 |
| --- | --- | --- |
| 修复问题、微调 | 修订号 +1 | 1.0 → 1.0.1 |
| 新增功能（兼容） | 次版本 +1 | 1.0 → 1.1 |
| 架构调整、数据格式不兼容 | 主版本 +1 | 1.0 → 2.0 |

> ⚠️ `versionCode` 是**单调递增的整数**，与 `versionName` 无关，
> 每次发布都必须比上一次大，否则手机无法覆盖安装。

## 三、版本回退

### 场景 1：只想看看旧版本

```bash
git tag                     # 列出所有版本
git checkout v1.0.0         # 切到指定标签（分离头指针，只读查看）
git checkout main           # 回到主线
```

### 场景 2：撤销某次提交（已推送）

```bash
git log --oneline           # 找到要撤销的提交 hash
git revert <hash>           # 生成一个「反向提交」，保留历史
git push origin main
```

> 用 `revert` 而非 `reset`：revert 不改写历史，对协作安全。

### 场景 3：彻底回到某个版本（丢弃之后所有改动）

```bash
git reset --hard v1.0.0     # ⚠️ 之后的提交会丢失
git push -f origin main     # ⚠️ 强制推送，慎用
```

> 仅在确定要丢弃且无人协作时使用。

### 场景 4：只想装回旧版 APK

最简单——去 GitHub Release 页面直接下载对应版本的 APK，无需编译。

## 四、Git 工作流建议

### 分支策略

```
main           稳定分支，只接受测试通过的代码
└─ feature/xxx 功能分支，开发完成后合并回 main
```

```bash
git checkout -b feature/add-unit-test    # 开新分支
# ... 开发与提交 ...
git checkout main
git merge feature/add-unit-test
git branch -d feature/add-unit-test
```

### 提交信息规范

建议采用 Conventional Commits，便于日后检索：

```
feat:     新功能
fix:      修复问题
chore:    构建/配置/词库等杂项
docs:     文档
refactor: 重构（不改变外部行为）
perf:     性能优化
```

示例：

```
feat(write): 默写支持音标提示
fix(speak): 修复部分机型识别超时无反馈
chore(words): 补充四年级上册 Unit 3 词汇
docs: 补充构建故障排查章节
```

### 提交前自检

```bash
git status                  # 确认没有大文件/敏感文件被暂存
git diff --stat             # 检查改动范围
```

特别确认这些**没有**被暂存（应已被 `.gitignore` 排除）：

- `local.properties`（含本机绝对路径）
- `jdk17/`、`android-sdk/`
- `app/build/`、`.gradle/`
- `*.apk`、`*.jks`

## 五、升级依赖

当前技术栈版本：

| 组件 | 版本 | 位置 |
| --- | --- | --- |
| Android Gradle Plugin | 8.2.2 | `build.gradle`（根） |
| Gradle | 8.2 | `gradle/wrapper/gradle-wrapper.properties` |
| compileSdk / targetSdk | 34 | `app/build.gradle` |
| minSdk | 24 | `app/build.gradle` |
| JDK | 17 | 工具链目录 |

升级 AGP 时，**AGP 与 Gradle 版本必须匹配**（[官方对照表](https://developer.android.com/build/releases/gradle-plugin)）。
例如 AGP 8.2 对应 Gradle 8.2；若升到 AGP 8.5，Gradle 需同步升到 8.7。

升级后务必完整编译一次验证：

```bash
./gradlew clean assembleDebug
```

> 本项目**零第三方依赖**，因此没有依赖漏洞与版本冲突的烦恼，
> 升级只需关注 AGP / Gradle / compileSdk 三者。

## 六、日常维护速查

| 我想…… | 操作 |
| --- | --- |
| 换词库 | 编辑 `app/src/main/assets/data/words.json` 后重新编译 |

| 清理重建 | `./gradlew clean` |
